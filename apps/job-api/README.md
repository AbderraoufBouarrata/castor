# castor job-api

HTTP API for build jobs. Owns the Postgres schema (one table, `jobs`, which is also the queue).

Each user has at most one job in `queued`, `building` or `running`. Their other jobs stay `waiting` and enter the queue oldest first. A partial unique index on `telegram_user_id` enforces this.

Also serves the status page: a static `index.html` that polls `GET /api/v1/jobs`. There is no separate status app.

Progress: Fastify routes under `/api/v1` are done. The status page and the routes that move jobs through states are not written yet.

## Layout

| Path | What |
|---|---|
| `index.js` | Entry point: builds the app, listens, closes cleanly on SIGTERM |
| `app.js` | Builds the Fastify app and registers routes. Tests import this. |
| `dtos/` | Request DTOs: JSON Schema for body, query and params, validated by Fastify |
| `hooks/` | Request hooks. `auth.js` checks the bearer token. |
| `controllers/` | HTTP layer: routes with their DTO and auth, plus handlers that call the service and shape the reply |
| `services/` | Business rules. The only layer that touches the database. |
| `test/` | `node:test` checks, run with `npm test` |
| `prisma/schema.prisma` | Database schema: `JobState` enum and `jobs` table |
| `prisma/migrations/` | SQL migrations generated by Prisma. Commit these. |
| `prisma.config.ts` | Prisma CLI config (schema path, migrations path, `DATABASE_URL`) |
| `db.js` | Shared Prisma client. Import `db` and `JobState` from here. |
| `generated/prisma/` | Generated client. Not committed, rebuilt by `npm run db:generate`. |

## Requirements

- Node 22.18 or newer. The generated client is TypeScript, and Node runs it directly by stripping types.
- PostgreSQL 14 or newer

## First run

```bash
cd apps/job-api
npm install
cp .env.example .env
```

Fill in `.env`:

| Var | Value |
|---|---|
| `DATABASE_URL` | e.g. `postgresql://postgres@localhost:5432/castor` |
| `API_TOKEN` | Output of `openssl rand -hex 32`. The bot sends the same value. |
| `PORT` | Defaults to `3000` |
| `HOST` | Defaults to `0.0.0.0` |

Create the database if it does not exist:

```bash
psql "postgresql://postgres@localhost:5432/postgres" -c "create database castor"
```

Apply migrations, then generate the client:

```bash
npm run db:migrate
npm run db:generate
```

Start the API:

```bash
npm run dev
```

## Commands

| Command | What it does |
|---|---|
| `npm start` | Run the API |
| `npm run dev` | Run the API and restart on file changes |
| `npm test` | Run auth and validation tests (no database needed) |
| `npm run db:migrate` | Create a migration from schema changes and apply it (dev only) |
| `npm run db:generate` | Regenerate the client in `generated/prisma/` |
| `npx prisma migrate deploy` | Apply committed migrations without creating new ones (production) |
| `npx prisma migrate status` | Show which migrations are applied |
| `npx prisma migrate reset` | Drop all data, re-apply every migration (dev only) |
| `npx prisma studio` | Browse and edit rows in a web UI |
| `npx prisma validate` | Check the schema for errors |

Prisma 7 does not regenerate the client after `migrate dev`. Always run `npm run db:generate` after a migration.

## API

| Method | Path | Auth | What |
|---|---|---|---|
| `POST` | `/api/v1/jobs` | Bearer token | Submit a job. Returns 201 with the job, state `queued` or `waiting`. |
| `GET` | `/api/v1/jobs` | none | List jobs, newest first. Query: `telegramUserId`, `state`, `limit` (1-100, default 50). |
| `GET` | `/api/v1/jobs/:id` | none | One job, or 404. |

`POST /api/v1/jobs` body:

| Field | Required | Rule |
|---|---|---|
| `telegramUserId` | yes | Positive integer (`message.from.id`) |
| `repoUrl` | yes | `https://github.com/<owner>/<repo>` |
| `phone` | no | Digits, optional leading `+` |

Responses never include `phone`, because `GET /api/v1/jobs` is public.

Errors: `401` bad or missing token, `400` invalid input, `404` unknown job.

Examples:

```bash
curl -s -X POST localhost:3000/api/v1/jobs \
  -H "Authorization: Bearer $API_TOKEN" -H 'Content-Type: application/json' \
  -d '{"telegramUserId":111222333,"repoUrl":"https://github.com/x/y"}'

curl -s "localhost:3000/api/v1/jobs?telegramUserId=111222333&state=waiting"

curl -s localhost:3000/api/v1/jobs/<id>
```

## Changing the schema

1. Edit `prisma/schema.prisma`.
2. `npm run db:migrate -- --name <what_changed>` (e.g. `add_submitter`).
3. `npm run db:generate`.
4. Commit the schema and the new folder in `prisma/migrations/`.

## Using the client

```js
import { db, JobState } from './db.js';

const job = await db.job.create({
  data: { telegramUserId: 111222333n, repoUrl: 'https://github.com/x/y' },
});
await db.job.update({
  where: { id: job.id },
  data: { state: JobState.building, buildingAt: new Date() },
});
```

## Useful checks

Connect to the database:

```bash
psql "$DATABASE_URL"
```

List jobs:

```bash
psql "$DATABASE_URL" -c "select id, telegram_user_id, phone, state, repo_url, created_at from jobs order by created_at desc limit 20"
```

Count jobs by state:

```bash
psql "$DATABASE_URL" -c "select state, count(*) from jobs group by state"
```
